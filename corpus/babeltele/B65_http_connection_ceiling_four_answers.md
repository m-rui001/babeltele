### ⟦rfc2616⟧ ⟸ corpus/raw/httpKA/rfc2616.txt

8.1.4 Practical Considerations Servers will usually have some time-out value beyond which they will no longer maintain an inactive connection.

The use of persistent connections places no requirements on the length (or existence) of this time-out for either the client or the server.

Client software SHOULD reopen the transport connection and retransmit the aborted sequence of requests without user interaction so long as the request sequence is idempotent (see section 9.1.2).

Servers SHOULD always respond to at least one request per connection, if at all possible.

A single-user client SHOULD NOT maintain more than 2 connections with any server or proxy. A proxy SHOULD use up to 2*N connections to another server or proxy, where N is the number of simultaneously active users.

### 不可由在库文件判定(只写在这里, 不进判词与门槛)
四份 .txt 的抓取时刻与磁盘 mtime 谁新谁旧; rfc-editor.org 此刻给这四份挂的现行状态页与勘误页(是否已改动 2616 的 §8.1.4);各家浏览器此刻对同一域名实际同时开几条连接(2 条上限在 2014 年被撤, 但实现层的并行度从未由规范决定);现网服务器把空闲超时配成多少秒; 14⇎22 撤掉数字之后“保守地多开”在真实客户端里被解释成什么。
这些量要么在本机之外、要么随实现漂移, 复算通道里没有它们的位置; 若要把它们变成判词, 需要先取回带时间戳的另一手快照, 再按本注同一套键重跑——门槛只认在库字节。
