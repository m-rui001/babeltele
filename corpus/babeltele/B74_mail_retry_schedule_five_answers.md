5.3.1.1 Sending Strategy The general model of a sender-SMTP is one or more processes that periodically attempt to transmit outgoing mail.

The sender MUST delay retrying a particular destination after one attempt has failed. In general, the retry interval SHOULD be at least 30 minutes; however, more sophisticated and variable strategies will be beneficial when the sender-SMTP can determine the reason for non- delivery. Each set consists of <letter>,<cutoff time>,<arguments> The letter identifies the algorithm for computing a new retry time; the cutoff time is the time beyond which this algorithm no longer applies, and the arguments vary the algorithm's action. The cutoff time is measured from the time that the first failure for the domain (combined with the local part if relevant) was detected, not from the time the message was received. The available algorithms are: F: retry at fixed intervals. There is a single time parameter specifying the interval.

The main configuration variable retry_interval_max limits the maximum interval between retries. It cannot be set greater than 24h, which is its default value.

### 本注的判断
五份给的其实不是“三个不同的数”, 而是三种不同**类型**的答案, 而且这个类型差在字节上可数: 821 只交付类别(⟦821⟧⟨4yz Transient⟩ 与 5yz 相距 29 行)并当场自认“难定 transient”(⟦821⟧⟨It is difficult to assign a meaning⟩ 距前者 18 行, 经验法则再后 4 行), 它全份 retry 族 0 枚 ⇎ queue 族 0 枚 ⇎ 大写五轨只有 SHOULD 2 ⇎ MAY 1, 小写 must 却有 52 枚——它描述的是协议对答, 不是运维日程; 1123 第一次把日程写成三句义务(下限那句在 1123 全篇 1 枚 ⇎ “MUST be configurable”全篇 2 枚, 而主答段本身只 75 词), 5321 逐字收下(共头 35 词 ⇎ 共尾 9 词)却只多留一枚 MAY; 两份 MTA 一枚义务词也不给(段内三轨合计 0 ⇎ 0), 给的是能算的数——Exim 把整份日程压进一条规则串 * * F,2h,15m; G,16h,1h,1.5; F,4d,6h(3 段 30 档 345600 秒), Postfix 把日程摊成六个参数的默认值 432000 ⇎ 432000 ⇎ 300 ⇎ 4000 ⇎ 300 ⇎ 60。所以“多久再试一次”的五种答法, 在本库字节上是: 类别 ⇎ 下限 ⇎ 逐字继承+放宽一句 ⇎ 可解析阶梯 ⇎ 参数表, 而不是五个数。
“什么时候不再试”这一问只有两份答得到秒: Exim 的截止 345600 秒正落在 1123 那句“至少 4-5 天”的下端 ⇎ Postfix 的 maximal_queue_lifetime 432000 秒落在上端(窗两端各被一份踩住, 命中 2 处, 判定 1/1), 三份 RFC 一个也不给确切时刻——“cutoff”这个字样在 RFC 面上 0 ⇎ 0 ⇎ 0 枚, 只在 Exim 面 17 枚。换算表 10 档里有 4 档低于 1123 的下限(60 ⇎ 300 ⇎ 300 ⇎ 900 秒), 即两份 MTA 的**首档**都比主机要求的下限勤得多, 差别被阶梯吃掉: Exim 的 G 段 6 档几何级数(倍数 1.5)走到 74812 秒才停, Postfix 则用 minimal_backoff⇎maximal_backoff(300 ⇎ 4000 秒)与 queue_run_delay(300 秒)三档链把退避显式化(链上判定 1 ⇎ 1)。于是“放弃”的语义分家是可数的: 放弃=不再入队(Postfix 的参数说明 ⟦postfix⟧⟨Consider a message as undeliverable⟩)⇎放弃=截止时刻(Exim ⟦exim⟧⟨the cutoff time is four days.⟩, 该句距封顶句 118 行 ⇎ 距 30 分钟示例 51 行)⇎放弃=“一般要 4-5 天”的经验值(1123/5321, 其给弃句在两份各占 191 ⇎ 346 字符, 共头 23 词而共尾 9 词——同句不同尾)。
谱系声明 ⇎ 字面共有在本遍对不齐, 这是第五遍才显形的一条: 5321 抬头只写 ⟦5321⟧⟨Obsoletes: 2821⟩ ⇎ ⟦5321⟧⟨Updates: 1123⟩, 但句尺上它与 821 共用 41 句 ⇎ 与 1123 只共用 19 句(行尺 29 ⇎ 2 条)——它名义上更新的那份, 字面共有量只有它没提的 821 的一半; 4yz/5yz 那套类别语言是直接从 821 搬的, 而“重试下限”那段才走 1123。两把尺的差本身是版式的物证: 同两对, 行尺→句尺各增益 12 ⇎ 17 条(72 列硬换行把一句切成多行, 行尺看不见跨行的同文); 两份 MTA 与三份 RFC 之间共用句 0 句 ⇎ 共用行 0 条——同一句话在规范面与手册面上从来没有同形过, 但 Exim 自家面上就印着两条不同的 `* *` 规则行(2 枚 ⇎ 去重 2 枚, 前两段逐字相同只差末档 `* * F,2h,15m; G,16h,1h,1.5; F,5d,8h` ⇎ `* * F,2h,15m; G,16h,1h,1.5; F,4d,6h`), 而“默认规则”那一条在面上只印 1 处: 它就排在提示行后 3 行, 与自己首处差 0 行。搬字量的口径一变就翻倍, 所以本条不用“谁抄了谁”而用“两把尺给出的序是否一致”: 821·5321 > 1123·5321 在行尺(29>2)与句尺(41>19)都成立, 序稳 ⇎ 而 5321 的抬头对共有量最大的那一头(821)只字不提, 只把 1123 写进 ⟦5321⟧⟨Updates: 1123⟩。
术语换代也能落到枚数上, 且换代点唯一: sender-SMTP 32 ⇎ 17 ⇎ 3 ⇎ 0 ⇎ 0 ⇎ receiver-SMTP 41 ⇎ 21 ⇎ 5 ⇎ 0 ⇎ 0 ⇎ SMTP client 0 ⇎ 0 ⇎ 76 ⇎ 0 ⇎ 247——旧名在 821 满页(32 ⇎ 41 枚), 1123 减半, 5321 只剩 3 ⇎ 5 枚而 SMTP client 起 76 枚, Postfix 直接沿用新名 247 枚; 拼法也分家(queueing 0 ⇎ 3 ⇎ 0 ⇎ 0 ⇎ 0 ⇎ queuing 0 ⇎ 0 ⇎ 7 ⇎ 0 ⇎ 1), 5321 一份之内两种拼法并存(0 ⇎ 7 枚)。同一节里的义务词也在换代: 1123 段内 SHOULD 1 ⇎ MUST 2 ⇎ MAY 0, 5321 段内 1 ⇎ 2 ⇎ 1, 多出的那一枚 MAY 正是它相对 1123 的唯一语义增补(⟦5321⟧⟨may be appropriate to protect the host⟩), 19 枚新词与 2 枚失踪词的对称差 21 词把这次“搬家不是复制”钉住; 而两份 MTA 段内三轨全零 ⇎ 全篇语气 Exim 0 枚 ⇎ Postfix 26 枚——手册不谈义务, 只谈默认值。
